## Existing API activation and atomic admission

The existing `POST /api/planner/generate` selects V2 with `x-sylf-planner-contract: 2` or `?contractVersion=2`. Existing cookie authentication and `SYLF_PLANNER_V2_ADMISSION_ENABLED` still govern admission. The legacy branch remains available. No second endpoint, queue, scheduler, database lifecycle or execution writer was introduced; no deployment flag was changed.

`GenerateRequestV2Schema` bounds one or two selected targets and the complete request to 4 MiB. The body contains `schemaVersion: 2`, `requestKey`, `text`, `targets`, optional explicit `researchRequested`, owned `documentIds` and linked `parentAttemptId`. A NEW target contains canonical `intent`; an EXISTING target contains `planId`, `expectedIntentVersionId`, `expectedPlanningVersion`, `baseActiveRevisionId` and an optional final `intent`. Existing source/evidence verification rules reject client-forged research or mastery. Client budgets, permissions, duplicate targets/documents and document use without research authorization are rejected.

`GenerationService.accept` composes existing IntentService saves and AttemptService enqueue in the existing user-coordinated transaction. Membership, version, intent and active-baseline checks precede edits. A failure rolls back both selected Plans, immutable versions, supersession and enqueue. Budgets and the durable root are server-owned; research request identity and selected documents are saved with the same Attempt. Admission does not call a provider or modify execution.

A new admission returns 202; exact replay returns 200 and the original Attempt, even after intent/version progression or apply. Reuse of the same request key with changed input returns the existing idempotency conflict. Both responses contain `{schemaVersion:2,attempt,replayed}`, `Cache-Control: private, no-store` and a Location pointing to the existing owned operation route. The worker independently claims that durable Attempt and uses Step 5's existing supervised handlers.
