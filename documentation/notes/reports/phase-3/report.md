# Sylf Notes Phase 3 implementation report

**20 October 2026.** Phase 3 implementation is complete locally, with the release gates below. **No live Google acceptance, deployment, hosted migration, Phase 4 work or separate Study Workspace implementation is claimed.** Current behavior is specified in the [workspace/Drive contract](../../workspace.md) and [foundation contract](../../foundation.md).

## Delivered

- Dedicated shared Notes destination and a responsive library with nested folders, notebooks/pages, Recent, Favorites, Subjects, Trash, title/content search, sorting, grid/list, previews, rename/move, duplication, portable import/export, version history and explicit conflict review.
- Actual BlockNote/Yjs rich-text editing: headings, styles, lists/checklists, links, images, shortcuts, undo/redo, title autosave, transactional local saves and visible local/cloud/recovery states. Existing source history and merge identities remain authoritative; no ordinary-open JSON reseeding.
- Google-only Notes consent/broker, verified folder/descriptor/probe provisioning, refresh leasing, least-privilege file scope, immutable bounded packs, automatic foreground upload/download, retry/reconnection, restart-safe cursors, readback integrity and fresh-profile reconstruction. Real deployments fail closed until configured; there is no synthetic production grant.
- AES-GCM local vault with authenticated online unlock, encrypted retained bodies/titles/images/filenames/catalog caches, account/session fencing, immediate lock on broker 401, blocked logout on unacknowledged work, emergency export, retained upload downloads, integrity/index repair and raw encrypted-device preservation.
- Stable document/page/resource identities, optional existing-subject references and Notes-owned resume contracts. The [updated Workspace master plan](../../../workspaces/master-plan-october-2026.md) was saved **in full**. Workspaces remain a future orchestration layer; no duplicate document store, resource shelf, timer or progression engine was added.
- Additive broker metadata migration, Prisma generation, source/license notices and exact BlockNote covered-source distribution. Web/mobile prebuild hooks generate those artifacts. Shared mobile guards explicitly prohibit Notes server imports and Notes secret symbols.

## Architectural decisions

| Decision | Reason / consequence |
| --- | --- |
| Keep the Phase 2 repository, Yjs 13 lineage and Sylf envelope v1. | One persistence/recovery authority; provider/editor independence and future native repository conformance remain intact. Exact dependency pins were retained. |
| Encrypt retained browser content; online cold unlock. | Resolves ordinary account-switch plaintext exposure without weakening Sylf authentication. Loaded unlocked tabs work offline. A cold offline page stays locked. No offline passphrase/PIN or persistent browser key was introduced. |
| Provider-readable cloud/export v1, with bounded same-origin relay. | Preserves approved storage direction and keeps Google credentials server-only. Pack bodies transit server memory but are not persisted in Sylf's database/storage. This is **not E2EE**. |
| Immutable packs up to 4,400,000 bytes; no mutable cloud head pointer. | Reduces small-file requests, preserves logical hashes and fits a complete 4 MiB object below the documented deployment payload limit. Lost responses reconcile by content rather than replacement. |
| Fresh proof before claiming current cloud coverage. | A past upload receipt cannot prove externally removed files still exist. Missing/corrupt copies preserve local source and visibly block fresh verified status. |
| Acknowledge discovery only after local activation. | Interrupted adoption cannot skip a downloaded page; restarted volatile cursors rescan. Unchanged acknowledged packs avoid repeated document-head writes. Incomplete initial scans never enable an empty replacement library. |
| No deletion/expiry/compaction of originals. | Trash, folder removal, session changes and subject changes retain note content. Native history and failed upload stages remain recoverable. History growth and large scans remain explicit scale limits. |
| Progressive loading and rendering. | Lazy editor, encrypted rebuildable catalog, bounded caches, yielding in-memory search, batches of 50 cards and CSS offscreen rendering. Full variable-height windowing and a disk full-text index were not introduced. |

Folder order/cycle projection, notebook page identities and conflict restoration reuse the foundation's contracts. Resume positions live in the existing synchronized Notes catalog, so simultaneous reading positions do not produce document conflicts. Whole-library backups include those positions; single-document archives retain the document source/history without the separate latest catalog position. Metadata changes retain all conflicting assets/pages/streams; history restoration creates a copy. Portable readable projections normalize absent formatting attributes only; the original native history stays byte-exact. All logout entry points reuse the Notes preflight, preserve existing pauses, and resume safely drained editors when preparation is cancelled. Failed network sign-out locks Notes and is reported as unconfirmed rather than silently navigating as if the cookie was cleared. Replay also checks a local activity epoch before adopting remote heads, preventing a late asynchronous read from rolling back a newer local save frontier.

## External setup and remaining risks

Follow the concrete [setup and live checklist](setup.md). Existing Google client variables were present, but the Notes server key, exact public origin and an authorized Drive test grant were absent. No private cloud account was accessed. Required before rollout:

1. Apply/review the metadata migration, configure stable OAuth identity/callback/consent and server secrets, back up wrapped vault keys and the encryption key, then perform live Google and actual deployment-policy tests. Mocked consent success is not real-provider qualification.
2. Confirm the online cold-unlock/retained-encrypted-data policy. Server key/wrapped-key loss can strand unsynchronized ciphertext. Account deletion cascades the active wrapped vault key: its existing confirmation now explicitly warns to export unsynchronized Notes from **every device** first. There is no cross-device proof that all offline work was exported. An export/backup policy is essential; database and cloud history in their respective accounts are not independent backups.
3. Browser clearing/eviction/device loss can destroy unsynchronized local work. Memory-only edits and pending title input are not durable acknowledgements; process death can lose them. The UI distinguishes pending/saved status and offers recovery where the source capability remains available. No absolute no-loss claim is possible for browser-only storage.
4. Physical tablets/phones, Safari, WebViews, IME/composition, assistive technologies and native protected storage remain unqualified. The strict broker intentionally rejects arbitrary/native origins. A reviewed native authentication/return capability is required before production native Drive access; do not weaken origin checks.
5. Long histories/large bodies, cold pack discovery, export/import cancellation/progress and provider API costs require more qualification. Ancestor auditing/integrity paths can be quadratic, and scans/exports have finite memory budgets. Search coverage is bounded and disclosed. The final 1,000-document projection took 1.49 s on the test desktop. Asset object URLs currently live until the library closes; long image-heavy sessions need further eviction/device qualification before expanding attachment limits. No history pruning, unlimited library size or continuous background upload is promised.
6. Portable recovery currently restores the original enrolled owner/library. Cross-account/provider migration, automatic raw-device-snapshot restoration, scheduled independent backups and automated repair of damaged/moved provider originals remain separate work. Keep corrupted originals and raw copies; restore verified source through the documented recovery paths rather than deleting/re-provisioning.

## Phase 4 handoff

The stable envelope/repository, page/asset identities, editor adapters, transport contracts, local vault and resource references are ready for the next phase's design review. First close the applicable deployment/live/device gates. Future handwriting/PDF/OneDrive work must reuse this source/persistence/history and obey the [Workspace ownership plan](../../../workspaces/master-plan-october-2026.md). Native storage may move earlier if physical-device evidence requires it. No Phase 4 or separate Workspace implementation was started.
