# ADR 0002 — Sylf Native workspace foundation

**Status: Accepted with Phase 3 (30 October 2026), subject to the owner's Phase 3 review.** This implements [ADR 0001](0001-technology-stack.md). The evidence is in the [Phase 3 report](../reports/phase-3/report.md), and the working guide is [`native/README.md`](../../../native/README.md).

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| 1 | Sylf Native lives in a top-level **`native/` npm workspace** (`apps/*`, `packages/*`) with its own lockfile. The root package does **not** declare workspaces. | Expo 58 pins React 19.3.0 while the web app pins 19.2.4. A separate install tree keeps the web app's install, build and imports exactly as they were. |
| 2 | Root `tsconfig.json`, `eslint.config.mjs` and `vitest.config.ts` each **exclude `native/`** (one line each). These are the only root changes. | Root tools glob the whole repository. Without the exclusions, `next build`'s type check and root lint and tests would process native sources with web types. |
| 3 | Approved `lib/` modules are consumed **in place** through `@sylf/shared` (`packages/shared/src/index.ts` is the allow-list). Nothing is moved or copied. | Preserves web imports. Phase 2 measured identical results across engines. |
| 4 | **Single-copy resolution** for stateful libraries is enforced three ways: the Metro resolver (bare imports from `lib/` resolve as if imported by the app; resolving into the web app's `node_modules` fails the build), TypeScript `paths`, and Vitest `dedupe`. `check-single-copy` also audits the install. | Phase 2 reproduced Yjs's duplicate-instance hazard. |
| 5 | **Client/server boundary** is enforced at build time (Metro throws `SYLF_NATIVE_BOUNDARY`) and statically (`check-boundaries` walks the allow-list's full import graph and every native source). A single list in `tooling/metro/boundaries.js` mirrors `mobile/vite.config.ts`. | Server code and credentials must never enter client bundles (AGENTS.md). |
| 6 | **Platform adapters** live in `@sylf/platform`. Small interfaces cover crypto (implemented), storage, pen, PDF, audio, session and files (declared and scheduled). `implementation.native.ts` and `implementation.web.ts` are selected by Metro through relative imports, and `detectCapabilities()` plus `windowSizeClass()` drive behavior. | ADR 0001's "native modules on tablets, existing web owners on desktop", without premature implementations. |
| 7 | Native code ships as **local Expo modules in `packages/`** (pattern: `@sylf/native-platform`, Kotlin and Swift), autolinked through the workspace. | One mechanism for every later native module (ink, PDF, session, World host). |
| 8 | The **Electron host** loads the web build from a privileged `sylf://app` scheme, not `file://`. It uses a strict CSP (no eval or inline scripts), a sandboxed, context-isolated renderer, a frozen two-key preload bridge, no navigation or new windows outside the app, no permissions, and a single instance. A `--sylf-self-test` mode verifies these behaviorally. | Electron security checklist. Electron 45 has no getter for live web preferences, so verification observes behavior. |
| 9 | **Continuous Native Generation.** `apps/sylf/android` and `ios` are generated by `expo prebuild` and git-ignored. Provisional identifiers are `app.sylf.client` and scheme `sylf-native`. React Native 0.88's default Android toolchain is used (compileSdk 37, build-tools 37.0.0, NDK 27.1). | Reproducible native projects. `app.sylf.native` was rejected because `native` is a Java keyword. The final identity is open question C1. |
| 10 | **Design direction:** the design-system package carries only user appearance preferences, color math and a temporary diagnostics palette. The visual language is created fresh in Phase 4 (master plan §7.2). | Owner direction, 30 October 2026: the web app is not a design template. |
| 11 | **Deferred deliberately:** Electron packaging, signing, fuses and auto-update (Phase 17); React Native Skia, Reanimated and Gesture Handler (added by the phase that first needs them); expo-sqlite and the native Notes repository (Phase 12/14); expo-system-ui (Phase 4, with theming). | No unnecessary dependencies in the foundation. |
