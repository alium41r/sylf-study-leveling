## Implemented foundation

Plan identity remains the existing PlannerPlan. PlannerIntentVersion stores immutable owned canonical intent ancestry. PlannerAttempt is the durable job/root request, independent of immutable revisions. Existing revisions hold sealed V2 educational/execution/context/quality artifacts; working intent, active revision and candidate are separate truthful pointers. Accepted intent edits supersede in-flight correspondence instead of relabeling an old result. Changing strategy creates an intent version, not another planning engine. Workspace is an owned projection, never an independent persistence system.

Attempts persist idempotent request hashes, selected target/base/intent correspondence, budgets, checkpoints, provider/quota receipts, lease owner/fence and results. Publication atomically seals the revision/change set and candidate pointers under currentness checks. Read-only research has zero targets and no apply receipt; trusted research resolution can bind canonical derived intent once across selected targets without changing hard facts. Public inputs cannot forge verified sources, readiness results or observed execution. Owned-document verification/import intelligence remains Phase 2 and currently fails closed.

The compiled worker uses the same repositories as web, a separate four-connection pool, two concurrent jobs and user admission/fairness. Forty-five-second leases renew every ten seconds; database-time fencing rejects stale owners and late publication. Independent recovery retains original deadline/counters/checkpoint and uncertainty. Cancellation and shutdown cannot refund dispatched usage or accept late result mutations. Foreground call/quota receipts transfer into one root exactly once. Unknown cost is represented explicitly; historical zero estimates are preserved and reported as unverified rather than certified as zero spend. Phase 1 registers **no generation or research handler**: the packaged worker is live/schema-compatible, deliberately not generation-ready, and cannot fabricate output. See [runtime/deployment and recovery](WORKER_RUNTIME.md).

One ApplyService verifies sealed content, full semantic diffs, current intent/base, live capacity, prerequisites, owned references, quality correspondence, acknowledgments and execution versions before materializing. It updates Goal, Quest, links, both target pointers and the receipt in one serializable transaction. Concurrent confirmation returns the same receipt; failures at Goal/Quest/link/pointer/receipt boundaries leave neither target partially applied. “Kept” preserves Quest rows exactly. Changed instructions/criteria are semantic changes. An unstarted edit retains identity; started content/timebox/history/rewards are protected. Acknowledged pause permits reviewed remaining placement/estimate changes. Withdrawal preserves actual history with zero future commitment; a continuation has distinct lineage and cannot award completion on its withdrawn original.

Shared execution context separates approved total timebox from remaining forecast and accepted actual time. Placement validation counts eligible commitments and actual effort once; the durable layer verifies allocations but **does not implement a scheduler/compiler**. Completed hard-window prerequisites anchor to accepted completion dates. Unselected cross-plan dependencies are owned and pinned; two newly created prerequisites may materialize together in a joint apply. Canonical time semantics are shared by Quest reads, legacy availability adapters, calendar/daily statistics, Focus/session settlement and capacity. Explicit work completion is distinct from session end and mastery.

Versioned StudySession start/restore/progress/pause/resume/end requires owned execution versions and durable transition receipts. Zero-second start protects work. Server PAUSED/ENDED state overrides browser storage; local epoch accounting and tab leadership remain their existing owners. The shared web/mobile Focus transport recovers lost responses, serializes transitions and rejects stale-device state. Ended-session restoration displays completion of the session without completing study work. Existing economic RPCs, XP/SP/Sylph ledgers and weekly mission settlement remain transactional authorities.
