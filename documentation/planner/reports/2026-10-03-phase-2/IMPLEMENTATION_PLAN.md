# Planner V2 Phase 2 execution roadmap

This records the approved six-step roadmap used by this implementation. The [V2 target architecture](../../PLANNER_TARGET_ARCHITECTURE.md), [final architecture review](../2026-10-02-final-architecture-review/REVIEW.md), [audit](../2026-10-02-end-to-end-audit/AUDIT.md), [Phase 0](../2026-10-02-phase-0/README.md) and [Phase 1](../2026-10-02-phase-1/README.md) govern it. The older pasted proposal is design history; V2 explicitly supersedes conflicting earlier proposals. Reports describe evidence from their own runs.

AI owns educational judgment. Deterministic code owns hard facts, scheduling, identity, lifecycle, validation and execution. Extend existing owners; preserve the frozen contracts and Phase 1 durability. No new workflow tables, event bus, optimizer, parallel execution engine or separate Free/Pro compiler.

The [requirement map](REQUIREMENTS.json) identifies source sections, audit findings, systems, workstream, execution step and completion gate. `SCHEMA_ONLY` means a supporting data boundary exists; its producing service and lifecycle integration still require implementation and evidence.

Budget gates use the frozen profiles: advice/calendar-only 2 calls/30 seconds, educational 6/180 seconds and research 8/300 seconds, with their existing token limits. Planning calls are capped at five; research syntheses at two; research processing has a 120-second sub-budget. Interpretation, OCR, fallback, adaptation, review, repair and verification share the root budget. A lease takeover never extends its deadline. A terminal retry is a new explicitly requested attempt linked to the prior checkpoint.

Reuse Phase 1 Plan/Intent/Attempt/Revision/ChangeSet/ApplyService, database-time leases, fencing, writer coordination, owner/reference checks, mutation guards, quota accounting and execution-context correspondence. Any necessary persistence additions extend existing Plan/check records with migrations, Prisma generation and schema build version changes; Step 1 needs none.

Calendar-only educational reuse remains an invariant. Implementing Phase 4's selective semantic update closure, continuation/withdrawal journeys and linked-edit product flows is outside this phase. Phase 3 Planner UI and Phase 5 held-out 100-case/human/manual-comparison/usability acceptance remain outside scope. Initial bounded joint blueprint generation is part of Phase 2.

An implementation conflict stops that specific path. Record the evidence and smallest proposed deviation before changing governing design. Successful parsing is not completion: Phase 2 finishes only after the producing services, actual runtime, lifecycle integration, required evidence and completion report pass.
