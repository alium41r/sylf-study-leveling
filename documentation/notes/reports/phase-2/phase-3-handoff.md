# Phase 3 handoff — typed Notes cloud alpha

**20 October 2026. Handoff only; Phase 3 has not started.** Read the [current foundation contract](../../foundation.md), [Phase 2 results](report.md), [Phase 1 contracts](../../architecture-contract.md) and [Phase 0 roadmap](../phase-0/report.md). Use the production modules and their conformance tests; the Phase 1 prototypes are historical evidence.

## Decisions before exposing Notes

1. Approve the trusted-device/offline-access and logout-retention privacy policy. Phase 2 fences application access but retains plaintext owner-scoped IndexedDB; it does not provide a cryptographic local vault. Decide whether this is acceptable for the alpha or whether OS/native protected storage or a recoverable local encryption design must come first. Do not add an offline session bypass.
2. Approve the durability promise: acknowledged local saves survive the tested renderer and disk-backed browser-process crashes, but browser clearing/eviction, device loss and power loss are outside that guarantee. Unsynchronized work has no independent backup. If the product requires stronger guarantees, qualify native storage/backup earlier. Do not describe provider history in the same account as independent protection against account deletion.
3. Keep provider-readable cloud v1 provisional, as authorized for Phase 2. Any later E2EE change needs a separate format/key/recovery design and migration review. No automatic retention expiry or destructive garbage collection is approved.

## Work sequence and acceptance gates

| Order | Work | Acceptance before proceeding |
| --- | --- | --- |
| 1 | Notes-specific credential broker and binding model proposal, reusing existing security patterns. | Separately reviewed schema/migration proposal; `getSession`, ownership, origin/CSRF controls, PKCE/state, encrypted purpose-bound credentials, refresh leasing and callback allowlisting. Keep Notes authorization distinct from calendar grants. Never put provider secrets in shared/mobile imports. |
| 2 | Google `drive.file` provisioning and immutable transport. | Registered development/production callbacks; authorized disposable test account; stable account/root validation; create/read/hash probe; verified descriptor enrolment; restart discovery; scope mismatch/revocation/account-switch tests. Mandatory cloud connection enforced before document creation. No synthetic production bindings or local-only onboarding. |
| 3 | Provider object packing/discovery and transfer qualification. | Run actual same-origin CORS/CSP/token tests; approve narrowly scoped destinations; do not log upload URLs or tokens. Benchmark small-object batching/packs against quota/API costs and interrupted upload reconciliation. Preserve logical object hashes and the existing transport semantics; requalify any contract change. Measure long histories and missing indexes, not only 200 revisions. |
| 4 | Useful typed Notes workspace, shared with mobile. | Reuse Sylf shell/auth/theme/API systems. Library: Recent, All, Favorites, Subjects, Trash and optional folders. Notebook means ordered pages inside a document. Minimal rich-text schema first: paragraphs, headings, basic styles, lists, links and attachments. No ink/PDF editor yet. Subject lifecycle never deletes notes. |
| 5 | Visible save/sync/recovery experience. | Distinguish saving, local durable/pending cloud, verified cloud, blocked and corrupt states. Display exact cloud revision coverage and storage pressure. Handle rejected logout, retry and memory recovery; provide emergency export before navigation. Pending assets remain discoverable. Add verified library-header recovery without implicit account/root rebinding; preserve a raw database export if the header is unreadable. Show concurrent deletion/metadata alternatives and explicit restoration; never silently replace them. |
| 6 | Offline shell and device qualification. | Versioned static shell/update rollback, no authenticated-response/token caching, approved local unlock policy, offline cold boot and session-expiry/logout tests. IndexedDB estimate/persistence requests are advisory. Test physical tablet/mobile browsers and WebViews, IME/composition, accessibility and custom appearance modes. |
| 7 | Alpha release evidence. | Full relevant regression, web/mobile builds, fresh-device cloud restore with missing catalog, quota/throttling/uncertain upload, simultaneous devices, recovery export/import, hostile import corpus and source/license notices. Confirm original assets and native revision identities survive. Independent backup workflow must be explicit. |

Use `createBrowserNotesSession(ownerId, guard)` only after AuthProvider confirms the owner. Create one repository for an enrolled owner/library/generation; close streams and editor adapters on teardown. `NotesStream.open()` performs same-owner memory recovery before loading the native stream. Handle asynchronous mounting/teardown cancellation in the future React integration; repeated mounting of the current adapter is covered, but no production Notes hook exists yet.

No worker is scheduled by the foundation. A future foreground sync owner can use durable outbox claims; browser suspension still prevents upload guarantees. Keep polling fallback. Do not promise local history growth is bounded: checkpointing currently retains every source revision. Move explicit recovery scans and large export/import work off the UI thread with cancellation/progress before expanding limits.

OneDrive parity, handwriting qualification and PDFs follow the Phase 0 sequence. OneDrive requires delegated AppFolder grants tested on both personal and school accounts; resumable endpoint support must be verified separately. Future native SQLite/files adapters must pass the same repository contracts and byte fixtures plus platform crash/power-loss tests. Capacitor reuse is not such a qualification.

No Phase 3 implementation, OAuth setup, schema migration or production Notes UI was performed in Phase 2.
