# Shared mathematical rendering fix

Date: 2026-10-16. Scope: existing Markdown owner used by Sylvie, quick popup, Focus chat, Planner Copilot, formulas, Scratchpad and compact notification previews. No provider requests, production deployment, database changes, abandoned node-system work or unfinished Planner changes.

## Causes and fixes

1. **Incompatible KaTeX JavaScript and CSS.** The app loaded `katex@0.18.4` styles while `rehype-katex@7.0.1` rendered with its nested `katex@0.16.47`. The renderer emitted `.base` and related classes, while the newer stylesheet expects `.katex-base`. Browser inspection confirmed missing positioning/nowrap styles, wrapped fraction contents and overlapping symbols. The root package now pins the existing 0.18.4 release and uses npm's `$katex` override so the renderer, parser and stylesheet share it. A dependency-resolution regression test protects this invariant. No other package version was upgraded.
2. **Incomplete delimiter handling.** The screenshot's orphan `$\mathbf j` was plain Markdown text; a well-formed version renders normally. The shared remark transform now recovers only complete, recognizable vector/accent/symbol atoms after an orphan dollar, leaving following prose outside math. It does not guess a derivation or add missing braces. The original screenshot's stored production response was not fetched; the visible malformed-vector pattern was reproduced synthetically.
3. **Display equation parsing.** Same-line `$$...$$` becomes inline math in remark-math. Multiline fences with formula text on the opening line can treat that text as metadata and lose it. Shared normalization and the remark transform now preserve the expression, display intent and numbered-list indentation for dollar and bracket notation.
4. **Unsafe preprocessing boundaries and scattered spacing.** The previous bracket regex rewrote code examples. The replacement preserves fenced/inline/indented code, escaped backticks and literal escaped dollars; ReactMarkdown hides HTML comments without removing adjacent whitespace. Formula font size, baseline, vertical spacing and horizontal overflow now belong to one CSS module used by full and compact renderers. Wide inline fractions and display equations scroll locally rather than widening the transcript. Prose, lists and code retain their existing presentation.

The shared persona now asks every model to close delimiters, brace command arguments, place display equations on separate lines and keep prose outside math. This adds no AI call or retrieval. Existing output allowances, streaming, cancellation, accounting, persistence and copy behavior remain with their existing owners. Rendering never rewrites stored/copied content. KaTeX retains `trust: false`, with explicit expansion/size bounds and neutral styling for invalid-expression fallback.

- TypeScript and changed-file ESLint passed. Production webpack build and mobile build/bundle verification passed; generated mobile artifacts were restored afterward.

## Limits and release

These are local component/browser tests with synthetic replies, not a live-provider or hosted-production certification. Arbitrary invalid TeX, missing arguments and unsupported LaTeX packages cannot be safely inferred; their source remains visible instead of crashing or silently deleting an expression. An unfinished streamed expression can remain source text until enough content arrives. Screen-reader speech was not manually qualified.

Deploy the application normally, including `package.json` and `package-lock.json`, to update Vercel's renderer and styles together. Stored conversations use the corrected renderer on reopening; no data migration is needed. Relevant dependency mechanisms: [npm overrides](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#overrides) and [KaTeX HTML/CSS usage](https://katex.org/docs/node.html#including-in-webpages).
