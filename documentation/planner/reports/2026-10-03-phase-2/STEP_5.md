## Implementation

- `intelligence/quality.ts` builds independent review and exact issue verification from freshly loaded original requested and resolved goals, raw bounded evidence/provenance, adopted excerpts/authority/applicability, exclusions, complete dispositions and phases, original split receipts, uncertainty and actual allocation. Grounding paths point to facts already in the prompt; server-side exact excerpt validation uses those same facts. Generator explanations cannot substitute for evidence. Report identities/status/digests are server-owned. Preference findings become advisory, reasonable uncertainty remains explicit, and blocking findings need concrete requirement/observation and offending proposal anchors.
- `server/compiler.ts` composes the existing ResearchService and LearningCompilerService with review, at most one logical repair, revalidation, deterministic re-allocation and exact named issue verification. All external attempts/fallbacks use the shared metered boundary and the same root. Saved pending stages remain unconfirmable. An accepted bounded repair response is checkpointed before re-allocation; takeover uses that receipt rather than dispatching another repair. A dispatched repair without a saved accepted response requires an explicit new linked root. Lost review/verification responses may be dispatched again only with durable metering and remaining root allowance.
- `server/compilation.ts` assigns stable server identities, preserves exact owned kept specifications, binds accepted resource versions and single-owner joint prerequisite edges, and builds frozen revisions and the full ChangeSet. Actual publication remains exclusively RevisionService.publish and its transaction, fences, current intent/context checks, placement/execution graph validation and atomic joint candidate pointers. The compiler never invokes ApplyService or writes execution.
- Supporting checkpoint receipts bind exact input, original findings, repair bytes, verification allowance and stable identities. The quality-stage receipt hashes the exact execution identity registry; modifying the registry after review fails closed. The reader checks repair content hash in addition to existing request/owner/root/authorization/intent/base/context/source/envelope/blueprint/allocation/quality correspondence. Explicit linked quality retries pin their original requested goals and parent checkpoint; a same-root takeover retains counters and deadlines.
- Research adoption recovery finishes only the already-verified owned receipt if a crash separates adoption and checkpoint rebinding. It neither adopts new evidence nor renews a research window. Owned documents are re-read before independent review, verification and publication.
- `main.ts` supplies PLAN/REPLAN/JOINT and research-advice handlers to the existing supervisor under the existing durable-core deployment flag. No API activation or environment/deployment change is made. Readiness, cancellation, deadlines, renewal, concurrency and fencing remain owned by the existing worker/AttemptService.

## Implementation refinements

No governing design or frozen contract changed. Supporting repair JSON is capped at 32 KiB. Before the only repair, reserve one verification call with the current complete input plus an 8 KiB growth allowance; recheck actual repaired input before dispatch. A larger repaired artifact is retained unconfirmable when it exceeds that allowance. This does not guarantee that every schema-valid maximal repair fits the frozen token envelope, and it never trims consequential facts to fit. Literal excerpt checks establish correspondence, while educational correctness remains AI judgment requiring Step 6 live qualification.
