## B: relevant authoritative context

The existing [context owner](../../../../lib/planner/v2/server/context.ts) still loads complete owned Quest/session history; confirmation never uses truncated history. Large histories use a selective dependency registry containing all open commitments, live sessions, selected active education, explicit pins, and the recursive hard/continuation prerequisite closure, including completed prerequisites. Missing prerequisites, duplicate identity, more than 400 required references or unresolved legacy commitments fail explicitly. Small histories retain the existing Phase 1 dependency selection. Publication, ApplyService and workspace validation can validate older historical pins against the complete owned snapshot even if the new registry omits unrelated completed history.

[Model context](../../../../lib/planner/v2/intelligence/context.ts) exposes `projectPlannerContext` over an owned snapshot and `loadPlannerModelContext` inside the existing coordinated transaction. The latter loads current owned intents/revisions for one or two targets, including imported legacy baselines. Each target retains its authoritative context/evidence seal. Models receive local Plan/scope/execution aliases; the durable execution registry stays server-side.

Required execution carries full instructions, criteria, resource version references, hard/continuation dependencies, completion/withdrawal state, execution generation, exact accepted seconds, remaining effort and re-estimate flags. Zero-second legacy and standalone live sessions remain explicit, with their accepted time already included in capacity; an unresolved older timer must be stopped. Learning evidence retains dates, source, reliability, scope and resource references. Opposing readiness reports are grouped for educational judgment. Saved check results remain dated self reports, never verified mastery; revision/item provenance is retained as digests, and unresolved legacy scope is disclosed. Existing canonical student-note/resource fields require no schema change. Saved subject metadata and relevant saved-node descriptions are unverified assessment hints, with exact-title selection and omitted-node counts; they cannot establish official assessed scope.

Complete relevant V2 completion history contributes to scope-specific completion/accepted-pace summaries, approved-estimate totals, dates and a source digest. Relevant manual/legacy completions matched through owned subject/goal identities retain observations with unresolved scope and explicitly unknown estimates. Per-goal usage uses the stored Plan goal even if the original intent omitted it. Completion/time cannot independently demonstrate readiness. Up to 20 recent optional examples are bounded with explicit omission counts. An identical local scope alias in another Plan does not establish relevance. The model view defaults to 128 KiB, configurable from 1 KiB through 4 MiB. Optional examples can be omitted; required facts are never prefix-trimmed. Oversize required context produces `PAYLOAD_TOO_LARGE`. Callers must choose a root-budget-compatible allowance; dispatch separately enforces its token ceiling. Incidental projection timestamps do not change the digest; dated evidence and consequential facts do.

New context seals add `model_learning_evidence` to the existing evidence registry, pinning relevant completion/pace sources and dated saved-check provenance. The original `saved_checks` digest remains intact. Older sealed artifacts continue validating the facts they originally pinned; new seals cannot omit/change the provenance pin. Previously resolved attempts/checkpoints with differing context fail staleness checks and require explicit recovery/retry rather than silent rebinding. All 12 frozen contract sources remain unchanged.

`executionCapacityLedger` is extracted from the existing placement validator. Confirmation and model envelopes charge accepted actuals to session civil dates and open remaining commitments to placement dates, once. Replaced selected work is excluded from other commitments; selected started work reserves remaining effort separately. Daily projection conservatively rounds actual effort into whole-minute capacity, exposes exact seconds, applies rest/floating/blocked/deadline exclusions, and reserves recovery capacity once. Week summaries include actuals/commitments outside the detailed window in the same week and per-goal usage. This supplies constraints; it does not allocate/split work. Unsaved availability requires explicit provisional inputs, and confirmation still requires accepted availability.

## C: shared metered dispatch

[Shared dispatch](../../../../lib/planner/v2/intelligence/provider.ts) reuses existing route/model configuration, factory, adapters, entitlements and quotas. `workerProviderMeter` uses fenced AttemptService reservations and commits dispatch before HTTP. `foregroundProviderMeter` uses owned AiUsageLog receipts. Each fallback is a separate durably accounted single upstream attempt. Missing adapter configuration makes no external request and consumes no provider call. No new workflow table, model registry, SDK, quota system or unmetered retry path is introduced.

Input reserves a conservative serialized UTF-8 upper bound plus framing allowance; output is explicitly capped by the shared workload. Every adapter receives `singleAttempt`, output bounds and abort signal. DeepSeek and Groq now normalize stop/tool-call, length and other finish reasons. Groq error-XML recovery cannot count as a valid single-attempt result. DeepSeek's existing alias/environment resolution determines the model recorded in the dispatch receipt. A caller's structured validator must accept a complete STOP response. Malformed/incomplete/truncated results cannot succeed. Actual usage settles before content validation, so invalid output/fallback is still charged. Raw provider reasoning and error text stay out of returned/persisted result metadata.

[Provider policy](../../../../lib/planner/v2/intelligence/provider-policy.ts) stores review/verification holdbacks in existing supporting payload/receipt metadata. Atomic checks preserve call, input/output token and five-call planning capacity. Holdbacks are future capacity, not fictitious external calls, and estimates cannot shrink across fallback/takeover. Educational work reserves initial review capacity. Repair requires a completed initial review dispatch plus a separate reserved verification call. A settled, validated review dispatch releases its holdback. `reviewCompleted` means the dispatch completed; it does not attest to educational quality passing. Independent semantic review/repair remains Step 5, and trusted callers must size estimates for complete review input. Unexpected actual overrun fails truthfully.

Pending calls use the existing database-bound root deadline/fence and poll owned lifecycle/lease state. Cancellation, supersession, lease loss and expiry abort upstream. An abort-ignoring adapter cannot return a successful late result. Optional shorter call timeouts permit separately metered fallback within the same remaining root allowance. `startResearchWindow` starts the durable 120-second sub-window before Step 3 search/fetch. Research/OCR require explicit RESEARCH profile selection/escalation and share that window; takeover never renews either deadline.

Foreground receipts retain database dispatch/completion times, root/profile identity and review holdbacks. One foreground call can be pending per root. Actual processing duration transfers exactly once with owned counters/quota/guard metadata; queue waiting grants no fresh processing time. Existing Phase 1 accounting-only callers retain their legacy transfer behavior. Unknown foreground accounting remains unqueueable until resolved through the existing accounting owner.

[Pricing](../../../../lib/ai/usage-pricing.ts) uses configured current/cached-input rates. Missing/invalid rates yield null cost, never invented zero. Missing/invalid usage retains conservative unknown spend. Known late usage reconciles only the owned financial receipt after cancellation/fencing; it cannot publish, mutate a terminal Attempt/checkpoint, refund dispatched quota or renew counters/deadlines. When actual overrun plus another uncertain reservation cannot fit the frozen budget schema, existing conservative stop semantics terminate the root while the financial ledger retains known actual usage. Closing after deadline uses terminal failure because PostgreSQL forbids further RUNNING writes.
