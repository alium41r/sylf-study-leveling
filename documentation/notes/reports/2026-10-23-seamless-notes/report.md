# Notes seamless startup and quiet synchronization repair

**23 October 2026 — local repair verified. Controlled deployment is waiting for the fresh Vercel CLI account-access confirmation. The existing public site has not yet received this repair.**

## Findings and fixes

- **Separate-site opening:** the client deliberately stopped before unlock on any noncanonical origin and offered a new-tab Open Notes link. Verified existing connections now open automatically on the same exact trusted Sylf deployment. The server recognizes only the configured origin and exact Vercel-supplied deployment/production identities, checks Origin against the request URL, and retains the canonical storage realm and OAuth callback. No arbitrary `*.vercel.app` allowlist or CORS/key-sharing bypass was introduced. First-time or actually revoked-consent setup can hand off in the same tab to the registered callback origin after draining edits. Its one-time connection hint is consumed before leaving, so reload/history does not restart consent.
- **Repeated reconnect prompts:** the observed real connection was already ACTIVE with a valid access token and retained refresh credential. The interface offered Reconnect for every cloud error. It now reserves consent repair for an actual authorization failure. Google refresh rejection `invalid_grant` is distinguished from transient/client-configuration failures; missing files produce recovery errors rather than false revoked-consent prompts. A stale refresh request can reuse another worker's newer credential only within the same original binding. Sylf session expiry remains separate and still fences keys.
- **Background activity loop:** cursor-only pulls, duplicate adoption and individual outbox receipts were broadcast as document changes. That made idle tabs dirty/reload state and wake further background work. Only actual native document changes now notify document observers. Duplicate adoption no longer increments unchanged document versions, while a missing derived index can still be rebuilt from preserved history.
- **Excessive history downloads:** the four-pack memory cache evicted packs that the adapter then fetched repeatedly for individual historical dependencies. Fully verified physical versions can now reuse matching locally hashed bytes within the unlocked session. A seven-pack regression verifies one download per pack, no repeat downloads for an unchanged pass, and refusal after a required cloud copy disappears. Cold sessions/changed listings do not trust old receipts as proof.
- **Intermittent opening:** document selection used server-component navigation for a local query change. It now uses Next's supported native History API integration on web and preserves the mobile/Capacitor navigation adapter. Latest-intent guards stop delayed navigation from dispatching an older selection; identity-scoped editor cleanup cannot erase the current editor's drain callback. Card navigation remains available while cloud synchronization is busy. The user's intermittent symptom was not reproduced on demand; these actual production paths and races have regression coverage.
- **Quiet interface:** routine saving/syncing buttons, sidebar pending text and text/handwriting/PDF saved labels are hidden normally. Admins enable diagnostics with `/notes?dev=true`. Local save failures, recovery needs, revoked consent, corruption and quota warnings stay visible. A transient network failure stays quiet; an ongoing failed backup with non-draft pending changes produces one static actionable warning after five minutes. Explicit retry resumes a network backoff without ignoring provider throttling.

Immediate local persistence, the 30-second cloud quiet period, periodic reconciliation, document-switch flushes, encrypted retention, native history and recovery remain in the existing owners. No dependency, schema migration, OneDrive or Workspace implementation was added.

This is real provider refresh, not a simulated OAuth response. It does not exercise revoked grants or a natural hour-long expiry wait.

## Deployment and remaining limits

**23 October follow-up:** this repair was included in the successful controlled production deployment recorded in the [Drive-cleanup report](../2026-10-23-drive-cleanup/report.md). Live authenticated opening, same-site synthetic-note navigation and quiet normal-mode controls were subsequently observed. The pending-deployment statement below describes the earlier qualification run, not current deployment status. The later [progressive opening repair](../2026-10-23-fast-opening/report.md) addresses additional startup latency.

- The production deployment/live fresh-tab check is pending Vercel's Allow Access action. Prior temporary CLI credentials were removed after Phase 7; a new private temporary authorization flow was opened for this candidate. No broader permission or temporary/unowned deployment was substituted. Complete the fresh-tab same-site and synthetic-note navigation checks after the controlled deployment before calling this repair live-verified.
- Use [the permanent Sylf address](https://sylf-alium41rs-projects.vercel.app/notes). Historical immutable deployment URLs retain old binaries. Browser storage is origin-scoped; this repair does not silently migrate or delete unsynchronized work from another origin. Authenticated aliases share the existing cloud library, not browser-local storage.
- Secure automatic opening still requires a valid Sylf session and online cold unlock. An already unlocked tab retains offline editing. Explicit browser-data deletion can remove unsynchronized work. Google can still require consent after a genuinely revoked/expired grant; local encryption remains intact and cloud storage remains provider-readable, not E2EE.
- Independent fresh-profile/device recovery and physical tablet/stylus qualification remain the earlier pilot gates. The real Chrome fixture verifies the shared screen with a synthetic provider; it does not qualify every browser, live offline internet disconnection or cross-device Google conflicts. No new public-release readiness claim is made.
