# Notes interface and unified pages

Current implementation: interface redesign Phases 1–3, 24 October 2026. See the [Phase 3 report](reports/2026-10-24-fluid-phase-3/report.md) for the continuous viewport, manipulation and print qualification. See the [Phase 1 report](reports/2026-10-23-interface-phase-1/report.md) and [Phase 2 report](reports/2026-10-23-creative-phase-2/report.md) for verification and limits. The [workspace](workspace.md), [ink](ink.md), [PDF](pdf.md), and [foundation](foundation.md) contracts remain the authorities for storage, authentication, recovery and synchronization.

## Library and editor

The library has a parent-first collapsible folder tree, folder cards, search, sorting, favorites, Trash, subjects, grid/list presentation and recovery. Prepared page thumbnails render actual text, images, paper and ink in their authored positions through the same bounded page renderer used for readable PDF copies. Other cards retain indexed text, original image assets and PDF previews. Visible previews are serialized and disposable; no second preview database is created. History previews pass their retained descriptor and revision heads, rather than reading the current document.

New note creates one note with typing and handwriting available. PDF, image and native archive imports use the existing encrypted asset/document owners. Legacy flow notes and typed/ink notebooks retain their identities and original adapters.

The unlocked library occupies the application viewport. A document hides the library navigation and outer containers. A compact contextual toolbar provides text formatting or handwriting, pinned text/pen switching, top/bottom docking, focus mode and on-demand pages. Narrow screens scroll tools horizontally. Escape or the floating page navigator exits focus mode.

Zoom is bounded to 400%; its minimum is the smaller of 60% and useful fit width, with a 30% floor. Fit width follows viewport width changes until custom zoom; fit whole page is separate. Authored coordinates remain independent of the viewport. Typed content extends a logical page and caret movement scrolls to keep writing visible. A virtualized notebook viewport lays out all active pages, mounts only the nearby window, and clips each page canvas and paper pattern generation to the visible slice. Native text/ink editors remain the same owners. Scrolling updates the active toolbar, page indicator and local resource URL while preserving a focused writing box at page boundaries; page jumps, fit, bounded zoom, touch panning and resume share that geometry. Active editors and pages with pending page actions are retained during operations. Window eviction captures and drains native changes before releasing bindings; failed buffers remain recoverable through the existing owner.

## Additive page layers and content boxes

`NotesLibrary.ensurePageLayers` adds missing companion streams without replacing originals. A legacy flow's first page has a deterministic ID referencing its original text stream. Metadata writes and page additions serialize through the existing pause/flush/adopt boundary. Prepared pages retain the primary `streamId` and reference `extensions.textStreamId` and `extensions.inkStreamId`, using the existing `blocknote/0.56.0` and `sylf-ink/1` adapters. Copies remap both stream references and retain each stream's native contents independently.

The original rich-text fragment remains `body`. `PageBoxes` stores validated page-local geometry and stacking order in the **same text Y.Doc**, under `text-boxes`. Additional text boxes use unique `box-<uuid>` XML roots in that document. Their initial body and geometry are seeded together; an independently initialized `body` is never merged over an existing body. Legacy `extensions.textOrigin` supplies the primary region's initial geometry until it is arranged. Up to 64 box records are retained per page, including removed boxes.

Users can place, drag, resize and nudge independent text/image boxes. Screen-space snapping and alignment guides assist box and ink moves; Alt bypasses assistance. The Arrange content panel selects objects across up to 24 pages, supports precise X/Y and centering, grouping/ungrouping, stacking, and copying/moving selections to another page. Group metadata lives in the existing text stream under `content-groups`; dragging a member moves its mixed text/image/ink group. Cross-page changes are prepared on detached native documents and publish all affected stream deltas in a single document revision through the existing metadata queue. Moves retain original ink samples, cuts, transforms, assets and history; extra text roots are cloned to unique destination roots. Natural text height is measured without handles and persisted as geometry outside arrangement undo, so offscreen transfers grow their destination before print. Text width reflows rich text; its height is a minimum and content can grow. Image resizing preserves aspect ratio. Page content lists overlapping boxes and provides front/back ordering. Arrangement undo/redo is separate from native text and ink undo; removed box content remains available through undo and history. Original page text remains the title/primary editor owner. The active box supplies the shared formatting toolbar. A newly placed text box focuses after its native binding mounts.

All boxes use the shared page transform. Existing rich-text formatting, inline images and the adapter's independent durability lock remain intact. The ink controller ignores box handles and text controls, including their touch and keyboard input. Parent leave handling flushes all mounted text bindings, geometry and ink before navigation. The existing encrypted repository, journals, native archives, recovery and Drive synchronization persist everything. Search, readable archive projections and history text include additional text fragments.

## Handwriting

The shared model/controller/renderer offers ballpoint, fountain, brush, pencil and fineliner pressure responses, plus highlighter. The Pen studio contains width, opacity, color, solid/dashed/dotted styles, straight-line assistance, pressure response and smoothing. Stored samples retain pressure, tilt, twist and elapsed time. Tilt broadens the pencil shading geometry, while brush pressure receives a smoother response curve. Legacy brushes keep their original geometry; all renderer/export paths share the same nib function. Existing strokes without new options retain their original renderer defaults.

Users can save up to eight favorite pens in the Notes catalog; the first four are directly available in the notebook toolbar. PDF annotations reuse the same Pen studio and favorites. Notebook favorites read the shared catalog so preloaded pages reflect a newly saved pen. Line, rectangle and ellipse tools derive geometry from retained samples. Screen rendering, hit testing, selection, previews and PDF export share geometry and opacity helpers.

The eraser supports whole strokes and precise circular cuts. Precision edits store immutable cut operations on original stroke IDs. Remaining pieces are derived, so concurrent cuts merge without duplicate replacement strokes. Original samples remain intact; local undo removes its own cut while retaining remote cuts. Hit testing, lasso selection, rendering and exports respect erased gaps. Lasso selections can move, scale, recolor and receive the current pen style.

The imperative input/render loop remains outside React's pointer-sample path. Existing coalesced input, bounded live strokes, touch navigation, palm suppression, spatial index, raster/path budgets and save/recovery boundaries remain in use. Physical stylus latency and device palm rejection require hardware qualification.

## Page studio and saved defaults

A visual gallery groups fourteen templates under Basic, Academic, Planners and Journals: blank; normal/narrow/wide rules and grids; normal/narrow dots; Cornell notes; music staff; weekly and daily planners; reflection journal. Canvas and vector-PDF paper geometry share the template definitions.

Page controls provide paper/rule colors, spacing, Sylf/A4/Letter/A5/square/custom sizes, orientation, image backgrounds and layout. A size change reflows boxes and refuses to crop existing handwriting. Backgrounds and positioned images reuse authenticated encrypted assets, with 16 MiB upload and 32-megapixel UI decode limits.

Continuous paper grows within a logical page, and notebook pages scroll continuously in a virtualized viewport. Page breaks additionally show sheet guides. Readable PDF copies divide long logical pages into bounded full-sized printed sheets at the selected sheet height, including the final sheet. Physical A4/Letter/A5 dimensions come from the shared paper catalog; custom notebook geometry converts from CSS units to PDF points. Original source PDF coordinates keep their existing units.

`NotesLibrary.preferences` / `savePreferences` use the existing encrypted, synchronized **library catalog stream**. Defaults save template, paper/rule colors, spacing, sheet dimensions, layout and dark adaptation. New notes and image imports inherit defaults; blank pages inherit their notebook's style. Up to 24 named custom paper styles can be saved, reused and removed in My templates. These contain paper colors, pattern/spacing, dimensions, orientation, layout and dark adaptation. Background images remain assets of their document and are not copied into cross-document defaults or saved paper styles.

Optional dark-mode adaptation changes the displayed paper/rules and lifts dark ink for contrast. It never changes the original ink, paper, image colors or exported colors. Authored dark paper remains dark. Chrome follows Sylf's semantic appearance tokens and custom surfaces.

## Compatibility, print and boundaries

The native/database format versions are unchanged. Prepared layers require `page-layers-v1`; creative documents require `creative-tools-v1`. Older readers refuse unsupported documents rather than silently dropping new geometry or brush fields. Original streams, history, archives, asset ownership and recovery remain intact.

Readable PDFs combine ordered text/image boxes, backgrounds and native ink, using the application font stack, authored widths and browser shaping. Bounded sheet rasters retain that appearance; an aligned, invisible Unicode text layer with ToUnicode mappings makes typed content searchable/selectable, including surrogate pairs. Text projection and line measurements are cached across long-page tiles; canvas pixels, page count, characters and raster bytes remain bounded. Unusual large paper reduces raster scale to meet the pixel budget. The output is a readable derivative, not a tagged accessible PDF or an editable native archive. Prepared thumbnails use a smaller bounded derivative of that same renderer; ink previews yield between batches. Native source PDFs retain the existing source/vector export path and searchable original text. Typed PDF annotations use the same Unicode search layer, positioned through the source-page transform, while keeping their browser-rendered appearance. All existing export/page/byte limits apply; unsupported or oversized copies fail without replacing originals.

Phase 3 verification, remaining limits and release readiness are in the [Phase 3 report](reports/2026-10-24-fluid-phase-3/report.md). Live Google acceptance, physical-device input and academic-year scale qualification remain separate release gates.

## Editing polish (24 October 2026)

- **Zoom, scrolling and uninterrupted writing.** Two-finger pinch, Ctrl/⌘ wheel and trackpad pinch preview continuously via GPU-composited `translate3d` / `scale` transforms on the notebook track without resizing canvases mid-gesture, then commit `area` + `zoom` + focal scroll position atomically in `useLayoutEffect` (synchronously flushing page canvas paint). Discrete zoom buttons/shortcuts commit immediately. Page slice height stays constant across 160 px scroll buckets with 480 px overscan so scrolling never triggers `canvas.height` reallocation, and continuous-layout page heights snap to integer CSS pixels with seamless paper abutment. Touch and stylus-hand panning track viewport coordinates and release with momentum. Top-level document notices overlay without shifting the canvas under an active stylus, and `memoryPending` counts only retained recovery capsules or streams in `failed` state rather than normal in-flight `"saving"` writes.
- **Continuous pages grow ahead of the pen.** In `continuous` layout the page keeps at least 400 units of blank paper below the lowest ink and grows in 900-unit steps (limit 100,000). Height is saved after the pen lifts, never mid-stroke.
- **Paged pages continue automatically.** In `paged` layout, writing within the bottom 8% of the last page creates one following page (inheriting that page's style) after the pen lifts. An existing following page is reused, so no extra empty pages are created. Typed text in paged layout still extends its page and splits into sheets on print; it does not create a page.
- **Stylus buttons.** `lib/notes/stylus.ts` maps the barrel button and eraser end to none, pen, highlighter, eraser, lasso or pan; the mapping syncs in the Notes preferences (`stylus`). Capabilities (pen, buttons, tilt, pressure) are learned from real pen events and stored per device. Apple Pencil double-tap/squeeze and Samsung Air Actions are not exposed to web apps and cannot be customised.
- **Clipboard.** Ctrl/⌘ C/X copy and cut selected handwriting in Sylf's format (`application/x-sylf-notes+json`). Ctrl/⌘ V and the Paste button place handwriting, images (also drag-and-drop) or text as page content. Typed text keeps native paste. Delete removes a selected image/text box.
- **Controls.** Full screen uses Maximize/Minimize icons and requests browser full screen where supported; zoom is grouped as − / fit width % / + / fit page.
- **Page customization scope.** Templates, paper colors, rule styling/spacing, dimensions, orientation, layout mode, dark adaptation, and background images can be applied either to the current page or across all pages in the notebook via the Page studio scope selector, synchronizing across all mounted page editors and descriptor metadata.

Remaining limits: physical stylus, touch-momentum and browser-fullscreen qualification on physical test devices.
